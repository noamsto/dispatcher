# remote-host

- **Remote workers (`--host <name>`).** Runs the worker on another machine.
  - **Settings.** `hosts.<name> = {ssh, repos."owner/repo" = path, chrome?}`: `programs.dispatcher.hosts` in home-manager, or user settings. The ssh target and path always come from settings, never from a bus row. `chrome = true` marks a host that runs the owner's browser; `--host <h> --chrome` needs it.
  - **Preconditions.** The clone exists at the mapped path; `crew`, `dispatch` and `tmux` are on the remote's non-interactive ssh `PATH`; the remote's engine logins are present. A macOS remote needs a running tmux server started from the GUI login session (one first started by sshd cannot reach the login keychain). Use `--host` only from a streaming lane (`crew stream`, `crew fleet stream`); a park-lane dispatcher (cursor, codex, pi) never uses it (`crew watch` has no relay for remote events).
  - **Refused with `--host`:** `--add-dir`, `--base`, `--status`, `--lazy`, `--profile` (expand it first with `dispatch --profiles`; the remote resolves profiles against its own settings), and the env overrides `DISPATCH_PRECHECK`, `DISPATCH_IGNORE_RUNG`, `DISPATCH_SKIP_MODEL_CHECK`, `DISPATCH_SHAPE`, `DISPATCH_CLAUDE_CONNECTORS` and `DISPATCH_CLASS_SIGIL` (the remote never sees this env); under `--host` a claude rung or pace refusal means drop to the standard rung or ask the human. `DISPATCH_DRAFT_PR=1` is the one override that travels, as `--draft`. The engine roster is the remote's (`--agent` must be in its `dispatch --engines`); claude quota is checked locally; the remote judges the fan-out budget and load gate.
  - **Window.** The worker runs in a window of a remote tmux session: the one named like your local session at the dispatch or resume that opened the window, or `crew-<id>` if that ran outside tmux or an older version dispatched the worker. It is mirrored with `og-remote-open <ssh> <remote-session> --into <local-session> --window @crew_id=<id>` (no `--window` when the remote session is `crew-<id>`: that session holds only this crew's windows and is mirrored whole); otherwise dispatch prints `ssh -t <ssh> tmux attach -t <remote-session>`. Only `dispatch` and `dispatch resume` set the mirror up. After a local tmux or dispatcher restart, re-run that `og-remote-open`, taking `<remote-session>` from the `session:` part of the worker's `crew where` line on that host.
  - **Routed to the remote.** `crew reply`, `crew nudge`, `crew where` (prints ` [host <h>]`; the mirror window comes first), `permission-check` and `dispatch resume`. Name a remote worker by branch or codename, never by `%pane` (that host's, meaningless to local `tmux` and `crew where`). A routed `crew reply` runs there, so it is that host's reply that starts the lead's `crew nudge --wait` (see the dispatcher protocol's reply rule; `--no-nudge` opts out): never background a local `crew nudge --wait` for a remote lead. Exception: `permission-check --pane <%id> --branch <branch> [--answer]` takes the `%id` verbatim from the relayed `prompt:` detail. For any other `%id` from a batch carrying `host`, see the "verify, then act" recovery; never aim local `tmux` at it.
  - **Roster.** `crew roster` adds remote rows with `host` and `live` (judged on the remote's tmux). An unreachable host gives `host_error` rows with `state` and `live` null: never read that as dead.
  - **Inbox.** `crew inbox dispatcher:<c>` covers local rows only; a remote worker's messages arrive in stream batches (see "Read the bus").
  - **Broken link.** Exit 255 means the link dropped mid-dispatch and the remote worker could not be confirmed. Once the link is back, run the `dispatch --host <h> --recover <session> --crew-id <id>` the message names; it writes nothing when the remote made no worker.
  - **Holds.** `crew hold` does not record `--host`: name the host in the held spec's prose and re-pass `--host` on release.
- **Migrate a running worker.** `dispatch migrate <branch|codename|#N> --host <h> [--now] [--wait S]`, run by you (never from a worker env or pane), moves a live local worker to host `<h>`.
  - **Modes.** Cooperative (default): sends the worker a `migrate` directive; it checkpoints, pushes and posts `migrated` itself (`--wait`, default 1800 s). `--now`: no directive; stops the engine, snapshots tracked, staged and untracked work as one patch, and pushes only the worker's own commits, anchored on the repo's admin dir, through its hooks on purpose (never `--no-verify`, never force); a push failure comes back verbatim. The bundle (patch, transcript, handoff) lives in `<crew_dir>/migrate/<branch>/<UTC ts>`, never under `artifacts/`. Use `--now` only when the human is leaving now.
  - **Refused before anything stops (exit 2).** A worker env, a remote worker (already on a host), `add_dir:`, `base:`, `kind: review`, `lazy`, `code_mode:`, a lane `profile:`, an `## Owner authorization` section, and a host whose `dispatch --migrate-check` fails (no migrate support: update it first). Relay the refusal verbatim.
  - **Exit codes.** 0: done, or already migrated to that host. 1: failure. Push hook output and a worker `blocked` whose detail starts `migrate:` come back verbatim; a failed remote resume (worker stopped, marked migrating) → retry `dispatch migrate <b> --host <h>`, or abandon with `dispatch resume <b>`. 2: refused. 3: cooperative timeout (worker did not quiesce); the dispatcher sends `migrate-cancel`, which withdraws the directive (the worker's `migrated` is then refused) → ask the human; never rerun with `--now` on your own.
  - **`migrated` is not `failed`.** No attention item, no rating; the run continues on `<h>` and is rated there.
  - **Claim.** Released only to `<h>`; a dispatch to a third host stays blocked. After the local reap, that block rests on the remote row's 24 h freshness.
  - **Local reap.** `crew reap` removes the local worktree only once the remote row exists and the mark's tip is on origin; it never deletes the origin branch (the remote worker owns it).
  - **Engine context.** A claude transcript is carried and `--resume`d when possible, else the worker starts fresh from the handoff; the dispatch row's `engine_context` says which (and why when fresh).
  - **Does not travel.** Crew-dir critic artifacts, role panes (the remote grid restarts from `roles.json`) and `--add-dir` grants.
