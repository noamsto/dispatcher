# Design: native `dispatch` + concurrent crews

**Issue:** [#74](https://github.com/noamsto/nix-config/issues/74)
**Date:** 2026-07-12
**Status:** approved, pending implementation plan

## Problem

`dispatch` is a fish function generated by a Nix heredoc
(`home/terminal/fish/default.nix:199-406`). Two consequences:

1. **Not agent-native.** Claude Code's Bash tool runs bash, which can't see fish
   autoload functions, so every dispatcher agent must wrap calls in `fish -c
'…'`. The `/dispatcher` command carries a standing instruction to that
   effect (`home/ai/claude-code/commands/dispatcher.md:30`).
2. **One crew per repo.** `crew lock-role` mkdir-gates on
   `.git/crew/dispatcher.lock.d/` and _refuses_ a second dispatcher. Combined
   with the common-git-dir crew bus (`git rev-parse --git-common-dir`), this
   caps a repo — across all its worktrees — at a single active dispatcher.

Two latent problems fall out of the heredoc form:

- **Profile gate flattened to a constant.** Nix interpolates `${osConfig.profile}`
  into the fish source at eval time, so the work-only codex guard reads
  `test "work" = work` on this machine — a constant-folded no-op, not a live
  check.
- **Crew-id persistence is vestigial for agents.** The function does
  `set -q CREW_ID; or set -gx CREW_ID (crew id)` to persist one crew id across
  successive `dispatch` calls in an interactive shell. That only works in a
  long-lived shell; each `fish -c` is a fresh subshell and Claude Code's Bash
  tool does not persist env across calls, so the agent path silently re-mints a
  new crew id per call (fragments the crew) unless `CREW_ID` was already in the
  claude process env.

## Goal

- Make `dispatch` a **PATH binary agents call directly** — no `fish -c`.
- Support **concurrent crews per repo**, for both entry paths:
  - the `dispatcher` fish launcher (bakes `DISPATCHER_PROTOCOL.md` as a system
    prompt), and
  - the in-session `/dispatcher` slash command.
- Fix the profile-gate and crew-id-persistence problems as a consequence of the
  restructure, not as separate patches.

**Non-goals:** nested / sub-crews (a worker becoming a dispatcher); changing the
`events.jsonl` schema; a data migration (the schema is unchanged).

## Invariant change

Before: _one active dispatcher per repo_, enforced by an exclusive role lock.

After: _N crews per repo, each identified by its `crew_id`_; the bus separates
them by id. Crew ids stay unique-by-construction (`crew id` =
`timestamp-pid`). The bus data model already supports this — `events.jsonl` is
filtered by `crew_id` and `report`/`roster`/`inbox` already take a crew
argument. Only two pieces assume a single crew: the **watch cursor** and the
**role lock**.

## Crew-id delivery

Resolution order for `dispatch` (and, via `$CREW_ID`, for `crew`):

```
--crew-id <id>   (flag)   >   $CREW_ID   (env)   >   error with guidance
```

- **Launcher dispatchers** set `CREW_ID` in the claude process environment
  (`dispatcher.fish` already does `set -gx CREW_ID (crew id)` before exec'ing
  claude). Every Bash-tool subprocess inherits it, so the agent calls
  `dispatch …` with no flag.
- **In-session dispatchers** cannot inject env into their own already-running
  claude process. The agent mints an id once (`crew id`), then passes
  `--crew-id <id>` to `dispatch` and prefixes `CREW_ID=<id>` on `crew` commands
  (a one-shot env, already honored by `crew`'s `_crew_id`). This keeps the
  `crew` diff limited to the cursor + register changes — no new `crew` flag.

The `set -gx` mint is removed from `dispatch`; a native binary cannot export env
back to its caller anyway, and delivery is now explicit.

## Components

### 1. Native `dispatch` (bash)

- New file **`home/ai/claude-code/dispatch.sh`**, packaged with
  `pkgs.writeShellApplication` (name `dispatch`,
  `runtimeInputs = [ gh git worktrunk tmux jq gnused coreutils crew ]`),
  installed on PATH exactly like `crew`. The Nix heredoc in
  `home/terminal/fish/default.nix` is deleted.
- **Deviation from this spec:** the implementation omits `worktrunk` from
  `runtimeInputs` — there is no `pkgs.worktrunk`; `wt` comes from
  `programs.lazytmux.worktrunk.enable` and resolves from the ambient session
  PATH, which `writeShellApplication` preserves.
- **macOS compatibility:** `writeShellApplication` pins bash to nixpkgs bash
  5.x (not macOS system bash 3.2), and the declared `gnused`/`coreutils`
  runtime inputs put GNU `sed`/`date`/`mktemp` on PATH ahead of BSD userland.
  Script still avoids GNU-only flags where a portable form exists, as
  defense-in-depth.
- **Crew-id resolution** as above (`--crew-id` → `$CREW_ID` → error).
- **Profile gate** becomes a runtime read of an env var (e.g.
  `$DISPATCH_PROFILE`, set from `osConfig.profile` by the nix-generated
  environment) instead of a source-baked literal — one binary, correct on work
  and personal.
- **Ported 1:1 from the fish function:** arg parsing (tier / model / `--agent`
  / `--effort` / `--mcp` / `LINEAR-ID` shape-detection / free-form title),
  slug generation, `gh issue create` (or Linear id) with clean abort,
  branch/worktree-path computation, `wt switch -c`, `WORKER_TASK.md` stamping,
  codename/color via `crew identity`, `events.jsonl` dispatch log, and the
  tmux window scaffold (`new-window`, `set-window-option`, `send-keys` for
  claude/codex). Fish `string`/`set` builtins → bash parameter expansion,
  `sed`, and `[[ =~ ]]`.

### 2. `crew` changes

- **Per-crew watch cursor:** `$dir/dispatcher.cursor` →
  `$dir/crews/<crew_id>/cursor`. Core correctness fix — without it two
  concurrent dispatchers clobber one cursor and steal each other's `crew watch`
  events. (`DISPATCHER_PROTOCOL.md:64` already _claims_ a "per-crew cursor
  file" — this change makes the code match the doc.)
- **Per-crew watch lock:** `$dir/dispatcher.watch.lock.d` →
  `$dir/crews/<crew_id>/watch.lock.d`. Second single-crew assumption: the watch
  lock's error already says "for this crew", but the path is per-repo, so a
  second dispatcher's `crew watch` is wrongly refused. Per-crew path fixes it.
- **`lock-role`/`unlock-role` → `register`/`deregister`, non-exclusive.**
  `register` `mkdir -p`s `.git/crew/crews/<crew_id>/` and writes the dispatcher
  `pid`, never refusing; re-registering a live crew is idempotent. Crew ids are
  unique by construction (timestamp-pid), so there is no reclaim logic — a
  stale (dead-pid) entry is simply left in place, recorded for a future
  stale-cleanup command. The "a dispatcher already holds this repo's crew bus"
  refusal is deleted.
- No new `crew` flag: in-session dispatchers reach crew-scoped commands
  (`watch`, `inbox`, `send`, `report`) via the `CREW_ID=<id> crew …` env
  prefix, already supported by `_crew_id`.

### 3. `.git/crew` layout (shared across worktrees via the common git dir)

```
.git/crew/
  events.jsonl            # unchanged — already filtered by crew_id
  crews/
    <crew_id_A>/
      pid                 # dispatcher A's long-lived PID (for a future stale-cleanup command)
      cursor              # A's watch cursor
      watch.lock.d/       # A's watch singleton (one watch per crew)
    <crew_id_B>/ ...
```

Removed: `dispatcher.lock.d/`, `dispatcher.cursor`, `dispatcher.watch.lock.d/`.

### 4. Doc / launcher updates

- **`dispatcher.fish` launcher:** `crew lock-role` → `crew register`; keeps
  `set -gx CREW_ID` (env inheritance is how launcher dispatchers reach the
  native `dispatch`).
- **`/dispatcher` command** (`home/ai/claude-code/commands/dispatcher.md`):
  remove the "fish function; invoke as `fish -c`" note and the `lock-role`
  step. New flow: mint `crew id`, `CREW_ID=<id> crew register`, then
  `dispatch --crew-id <id> …` and `CREW_ID=<id> crew …`.
- **`DISPATCHER_PROTOCOL.md`:** drop "one dispatcher per repo"; document the
  `--crew-id`/env contract and the per-crew cursor.

## Error handling

- `dispatch` with neither `--crew-id` nor `$CREW_ID`: exit non-zero with a
  message telling the caller to pass `--crew-id` (in-session) or run under a
  launcher/registered session (env).
- `dispatch` in GitHub mode when `gh issue create` fails (issues disabled):
  abort before scaffolding a worktree — same behavior as today, with the
  "pass a Linear id" hint.
- `crew register` is idempotent; re-registering an existing live crew re-runs
  `mkdir -p` and rewrites `pid`. Crew ids are unique by construction
  (timestamp-pid), so there is no reclaim logic — a stale (dead-pid) entry is
  left in place, recorded for a future stale-cleanup command.

## Testing

- **Build-time:** `writeShellApplication` runs shellcheck on `dispatch.sh`;
  fix all findings before merge.
- **Concurrency (manual, end-to-end):** launch two `dispatcher`s in one repo;
  dispatch a worker from each; confirm each dispatcher's `crew watch` sees only
  its own crew's events and neither cursor advances past the other's events.
- **In-session parity:** run `/dispatcher`, mint + register a crew id, dispatch
  with `--crew-id`, confirm the worker window launches and the crew bus records
  the dispatch.
- **Cross-platform:** verify on Linux (`nh home switch`) and macOS
  (`nh darwin switch`).

## Migration

No data migration — `events.jsonl` is unchanged. Any live dispatcher restarts
after the rebuild (personal infra; acceptable). First rebuild removes the old
`dispatch.fish` autoload function and installs the `dispatch` PATH binary.
