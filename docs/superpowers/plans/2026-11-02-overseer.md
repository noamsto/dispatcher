# Overseer session — implementation plan

**Spec:** `docs/superpowers/specs/2026-11-02-overseer-design.md`. Its
component numbers are cited below as §N and its slices as S1–S7.

**Shape.** Seven slices, each its own issue, branch and PR, each mergeable
alone and each leaving the fleet working with no overseer running. Branch
off `main` unless a dependency below forces a stack; merge stacks bottom-up.

```
S1 ──► S2 ──► S4 ──► S6b ──► S7
        │     ▲       ▲       ▲
        └──► S5       │       │   (S5 also feeds S7)
        S3 ───┴───────┘       │
        S6a ──────────────────┘
```

Parallel-safe starts: S1 ∥ S3 ∥ S6a. Then S2 (after S1). Then S4 ∥ S5 (both
after S2; S4 also after S3). S6b after S2, S3, S4, S6a. S7 last. §6
(reporting) has no code slice: S2 supplies its data, S6b the `digestEvery`
setting, S7 the digest procedure in `OVERSEER_PROTOCOL.md`.

**Conventions for every step.**

- Work from the repo root; run commands in `nix develop -c …` (or a loaded
  direnv shell). Go tests run from `crew/`: `go test ./internal/<pkg>/...`.
- Bats files run with `bats <file>`; one case with `--filter '<regex>'`.
  Workers run targeted bats only; CI runs the full suite.
- Never read `.env*`, credentials or keys, and never print secret values.
- After touching a shell script, run `shellcheck` on it.
- Match the surrounding code's naming, comment density and error style;
  `dispatch.sh` is shfmt-excluded, keep its existing formatting.
- Test first: each step names the failing test to write before the code.
- Gate per slice (CI's commands): `nix flake check`,
  `nix develop -c bash scripts/bats-shard.sh --check`,
  `nix develop -c bash scripts/harness-inventory.sh --check`; new bats files
  get `tests/shard-weights.tsv` rows and `scripts/bats-affected.sh` mappings
  when `bats-shard.sh --check` asks for them.
- A new `crew` subcommand or flag also needs: kong wiring in
  `crew/commands.go` and dispatch in `crew/main.go`, a help text under
  `crew/internal/entry/texts/` (and its row in `texts/top.txt` or the parent
  text), and whatever `crew/internal/entry/help_screens_test.go` and
  `help_test.go` assert about help rows.

**Package direction (no import cycles).** Today `fleet` imports neither
`stream` nor `hold`, `stream` does not import `fleet`, and `hold` imports
only `ascii`, `bus`, `clock`, `jqrun`, `sender`. The plan keeps one
direction:

- `crew/internal/lane` (new leaf, S2): `State` (moved from
  `stream.laneState`, `crew/internal/stream/stream.go:327`, with only the
  inputs it reads) and `BusScratch` (moved from `stream.busScratch`,
  `crew/internal/stream/fleet.go:387`: `sha256(common)[:8]` hex-encoded, 16
  characters), plus `OverseerCursor(stateDir, host, common)` built on it.
  `stream` and `fleet` both import `lane`; no copies stay behind.
- `fleet → hold` (S2, S5): `fleet` reads outstanding holds through the
  already-exported `hold.Outstanding` (`crew/internal/hold/hold.go:168`,
  also used by `rosterrender/model.go:96`). `hold` never imports `fleet`: the fleet
  predicate reaches `crew hold due`/`park` as an injected
  `FleetDue func(...)` field on `hold.Options`, wired in `crew/main.go`.
- `stream → fleet` (S4): `stream/overseer.go` calls `fleet.Status`; `fleet`
  never imports `stream`.
- Each slice ends with `go list -deps ./...` building (a cycle fails the
  build) and `go vet ./...`.

## Steps

### S1. `crew fleet load` and `fleet_gate` over it (§4) — standard, claude opus

Touches the capacity gate every dispatch runs; opus for the parity
judgement. Issue title: "fleet: crew fleet load, and fleet_gate over it".

1. **Pin current behaviour.** Read `_fleet_leads`, `_fleet_finished`,
   `_fleet_owned`, `_host_load`, `fleet_gate` (`dispatch.sh:1328-1431`) and
   the `tests/dispatch.bats` cases matching `machine at capacity` /
   `ignore-budget` / `load average`. List every case; they are S1's parity
   suite and their assertions must pass unchanged at the end. Their harness
   needs two changes first, or every refusal case goes red for the wrong
   reason: the `crew` stub in `tests/dispatch.bats` logs and succeeds for
   everything except `pi-agent-dir` (`:29`, `:134`, `:232` `exec
"$CREW_REAL" pi-agent-dir`), so add a `fleet) exec "$CREW_REAL" "$@" ;;`
   arm to each stub; and cores come from a stubbed `nproc` on PATH
   (`fleet_nproc`, `:3055`), which the Go side must honour (step 3).
2. **Tests first** (`load_test.go`), with a fake tmux client and fixture
   worktrees: weight per tier (trivial 1, standard 2, deep 3, unreadable
   header 2); role panes ignored; a lead whose newest `worker:` status is
   `done|failed|exited|reaped` counts 0; a pane whose worktree is gone is
   ignored; `/proc/loadavg` fixture via an env override equal to
   `DISPATCH_LOADAVG_FILE`; `fleetBudget` 0 disables; the budget-cache
   summary marks an engine hot for a window ≥ 95 % with null or future
   `resets_at`, unknown (cache missing, > 2 h old, > 300 s future) as
   `in_budget: true` (fail open, as `_budget_query`).
3. **Implement `fleet.Load`** in `load.go`: reuse `repos`-style bus reads and
   `crew/internal/tmux`; read `fleetBudget` by running `dispatch-config`
   and decoding its JSON, the way `remote.Load` reads `hosts`
   (`crew/internal/remote/remote.go:103`), so Go never re-implements the
   settings layering (defaults, locked layer, user file, env override
   `DISPATCH_FLEET_BUDGET`, `dispatch-config.sh:440`). A `--budget N` flag
   skips that lookup: `fleet_gate` already holds the resolved budget from
   `$settings` and passes it, so `dispatch-config` runs only for standalone
   and `fleet status` use. Output the §4 document; `pending` is 0 until S5. Host probes keep `_host_load`'s
   sources and order (`dispatch.sh:1383-1393`): load from
   `$DISPATCH_LOADAVG_FILE` else `/proc/loadavg`, else `sysctl -n
vm.loadavg` (macOS); cores by running `nproc` from `PATH` (so the bats
   stub applies), else `sysctl -n hw.ncpu`; either unreadable → no load
   check (fail open). Never `runtime.NumCPU`.
4. **Wire** `crew fleet load [--json] [--budget N] [--add <weight>] [--own <branch>…]`:
   `--add`/`--own` let the gate ask "would this dispatch fit" in one call;
   exit 0 fits, 3 refuses with the `<why>` text `fleet_gate` prints today
   (`live lead weight W + this T dispatch (N) exceeds fleetBudget B —
heaviest: …` or `1-minute load average L is above the C cores`), 1 on
   error.
5. **Rewire `fleet_gate`** to call `crew fleet load --budget <resolved> --add … --own …` and
   print its `<why>` inside the unchanged refusal message and exit code;
   `--ignore-budget` keeps its "fleet check skipped" note. Remove
   `_fleet_leads`, `_fleet_finished`, `_host_load` once nothing calls them
   (`rg -n` first; `_fleet_owned` stays if the call site still needs it). An
   error from `crew fleet load` fails open with a stderr note, as the load
   probe does today.
6. Add a `tests/dispatch.bats` case: the stub makes `crew fleet load` exit
   1; the dispatch proceeds and stderr carries the fail-open note.
7. Run the step-1 parity cases and the new Go tests; `shellcheck
adapters/core/dispatch.sh`.

**Done when:** every step-1 case passes unchanged, `crew fleet load --json`
works from a non-git cwd, and `dispatch.sh` has no second weight
implementation.

### S2. `crew fleet status` (§1) — standard, claude opus

After S1. Issue: "fleet: crew fleet status — cold-start fleet view".

1. **Tests first** (`status_test.go`), fixture buses in temp git repos:
   - `dispatcher.state`: pid file with live pid → `live`; with a dead pid →
     `dead`; recycled pid (start after pidfile mtime + 2 s) → `dead`; no pid
     file → `closed` (use `crews.PidAlive` with a fake `proc.Table`).
   - `lane` from a fixture `stream.tick` (fresh, stale, dead) and `null` with
     none, via `lane.State`. First move `stream.laneState` and
     `stream.busScratch` into the new leaf package `crew/internal/lane`

     `stream` tests green before adding any fleet code.
   - `attention`: `unattended` / `idle` / `attended` per §1; a dead crew
     whose only live-state rows are `stale` is `idle`, not `unattended`.
   - remote workers: with `CREW_OVERSEER` set, `Status` passes no remote
     capture (no `remoteRun`, which sender-checks every remote argv as
     `dispatcher:<crew>`, `crew/main.go:1088-1099`, and S3 refuses that
     sender to the overseer); remote rows come from the local bus with
     `remote_unprobed: true`. Without `CREW_OVERSEER` the live merge runs

   - PR candidates: `pr_open` and `done` rows with `pr_url`; a `reaped` row

   - holds: outstanding quota holds listed with `kind: quota`.

   - non-git cwd works; a gone repo lands in `skipped`.
   - statelessness: with no overseer cursor seeded, two runs with the

4. **Table form**: one line per crew (`REPO CREW DISPATCHER LANE LIVE
BLOCKED(oldest) PR_OPEN HOLDS`); golden test.
5. Wire `crew fleet status [--json] [--gh]` before `Locate` (beside

### S5. Fleet holds, the shared queue and admission (§4) — deep, claude opus

After S1 and S2 (it fills S2's `queue` object). Issue: "fleet: fleet
holds, ordered queue and admission".

1. **Tests first** (`hold_test.go`): `crew hold add --fleet --prio high`
   writes `wait: {kind: "fleet", weight: W}` and `task.prio`; a fleet hold
   is excluded from `matured.jq`'s output (the null-`resets_at` trap: write
   this test against today's `matured.jq` first and watch it go red);
   quota holds unchanged.
2. **Tests first** (`queue_test.go`), fixtures over two or three repos in a
   temp registry:
   - membership from the registry only (a repo found only by the walk is
     ignored); a crew with a dead dispatcher, a `dead`/`stale` lane, or a
     live pid whose command line does not name the `dispatcher` launcher
     is parked; a `null` lane is eligible;
   - order: repo priority, then `prio`, then fairness (older last release
     first), then `ts`;
   - maturity: first fitting non-demoted hold; after `fleetBackfillAfter`
     only the head; `free` includes S1's `pending`; nothing is due while
     `load_over` is true even when the weight fits; a demoted hold is due
     whenever it fits;
   - chained clock: anchor `A` = latest fleet-hold release row and
     `fleet-priority.json` `updated_ts`; head `head_since = max(ts, A)`;
     after demotion the next head's `head_since = max(ts, previous +
fleetHeadTimeout)`. Cases: a stuck owner that never runs `crew hold
due` is demoted at `fleetHeadTimeout` while a worker re-posts `done`
     every 5 min (worker rows never move the clock), after which another
     crew's hold matures; a second hold whose `ts` predates `A` is not
     demoted at the same instant as the first; a release resets the
     chain;
   - evaluators are read-only: `crew hold due`, `crew fleet queue`,
     `--admit` and `crew fleet status` leave every `events.jsonl` unchanged;
   - `--admit <w>` refuses while an eligible non-demoted hold waits, admits
     `--hold <due id>`, admits when only demoted holds remain, admits when
     no fleet hold is outstanding;
   - `crew fleet prio` refuses with `CREW_WORKER_ID`/`CREW_ROLE_ID` set or
     from a crew-stamped pane (the `sender` probes), writes `updated_ts`,
     and appends one audit line per change.
3. **Implement** `fleet/queue.go` (exporting `fleet.Due`) and
   `fleet/prio.go`; add `FleetDue func(...)` to `hold.Options`, set to
