# crew M0 — file-based coordination bus (Implementation Plan)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship M0 of issue #29 — a standalone `crew` fish function providing the file-based coordination bus primitives: repo-keyed `crew_dir` resolution, `crew_id` minting, an append convention for `events.jsonl`, and crew-scoped `roster`/`inbox`/`log` read helpers. Zero new runtime; no harness integration yet (that's M1).

**Architecture:** One nix-managed fish function (`crew`, via `xdg.configFile."fish/functions/crew.fish"`, matching `dispatch.fish`). State is a single append-only `events.jsonl` at `$(git rev-parse --path-format=absolute --git-common-dir)/crew` — shared per-repo across worktrees. JSON lines are built with `jq` (correct escaping) and appended with `printf` under `O_APPEND` (atomic for small lines). Reads are `jq` filters scoped to a `crew_id`.

**Tech Stack:** fish, `jq` (already used throughout the repo), git, Nix / Home Manager.

## Critical constraints (read before executing)

- **Symlink dangle (same as #21):** `xdg.configFile` symlinks resolve to the _main_ `~/nix-config` checkout, so a `crew.fish` added on this branch won't be live in `~/.config/fish/functions/` until merged + `nh home switch`. **Therefore develop and test the function as a standalone file first** (`fish` can `source` an arbitrary path), and only embed the _verified-identical_ body into `default.nix` at the end. Do not claim the nix-wired version works pre-merge.
- **JSON via `jq`, never hand-rolled** — fish string interpolation can't safely escape arbitrary `body` text. Build every line with `jq -nc --arg …`.
- **Atomic append:** build the line into a variable with `jq -nc`, then `printf '%s\n' $line >> $log`. `printf` of a <4096B string under `>>` (O_APPEND) is a single atomic write — concurrent appenders won't interleave. Do **not** pipe `jq … >> $log` directly (jq may emit multiple `write()`s).
- **`jq now`** returns seconds (float); `ts` is milliseconds → `(now*1000|floor)`. (This is a real `jq` process, not a Workflow sandbox, so `now` is allowed.)

## Task 1: `crew_dir` resolution + `crew id` minting

**Files:**

- Create (dev scratch): `/tmp/crew-dev/crew.fish`

- [ ] **Step 1: Write the resolution + `id` skeleton**

```fish
function crew --description 'File-based coordination bus: id/status/msg/roster/inbox/log'
    set -l sub $argv[1]
    set -e argv[1]

    # repo-keyed bus dir; --path-format=absolute so main-checkout and worktrees
    # resolve to a byte-identical path (load-bearing — see #29).
    set -l common (git rev-parse --path-format=absolute --git-common-dir 2>/dev/null)
    if test -z "$common"
        echo "crew: not in a git repo" >&2
        return 1
    end
    set -l dir "$common/crew"
    set -l log "$dir/events.jsonl"

    switch $sub
        case id
            set -q CREW_ID; or set -gx CREW_ID (date +%s)-$fish_pid
            echo $CREW_ID
        case '*'
            echo "usage: crew id | status <from> <state> [detail] [pr] | msg <from> <to> <body> | roster [crew] | inbox <agent> [crew] | log [crew]" >&2
            return 1
    end
end
```

## Task 2: append — `crew status` and `crew msg`

**Files:**

- Modify (dev scratch): `/tmp/crew-dev/crew.fish`

- [ ] **Step 1: Add the `status`/`msg` cases** (insert before `case '*'`)

```fish
        case status msg
            if not set -q CREW_ID
                echo "crew: CREW_ID unset (run: set -gx CREW_ID (crew id))" >&2
                return 1
            end
            mkdir -p $dir
            set -l line
            if test "$sub" = status
                # crew status <from> <state> [detail] [pr_url]
                set line (jq -nc \
                    --arg crew "$CREW_ID" --arg from "$argv[1]" --arg state "$argv[2]" \
                    --arg detail "$argv[3]" --arg pr "$argv[4]" \
                    '{ts:(now*1000|floor), crew_id:$crew, from:$from, to:("dispatcher:"+$crew),
                      kind:"status",
                      body:({state:$state}
                            + (if $detail!="" then {detail:$detail} else {} end)
                            + (if $pr!="" then {pr_url:$pr} else {} end))}')
            else
                # crew msg <from> <to> <body>
                set line (jq -nc \
                    --arg crew "$CREW_ID" --arg from "$argv[1]" --arg to "$argv[2]" --arg body "$argv[3]" \
                    '{ts:(now*1000|floor), crew_id:$crew, from:$from, to:$to, kind:"msg", body:$body}')
            end
            printf '%s\n' $line >>$log
```

- [ ] **Step 3: Test concurrent appends don't interleave**

```fish
fish -c '
    source /tmp/crew-dev/crew.fish
    set -gx CREW_ID conc-(date +%s)
    cd /home/noams/nix-config-worktrees/feat-29-crew-m0
    set -l log (git rev-parse --path-format=absolute --git-common-dir)/crew/events.jsonl
    mkdir -p (dirname $log); rm -f $log          # fresh file → clean atomicity measurement
    set -l big (string repeat -n 5000 x)         # >4096B (PIPE_BUF): forces any non-atomic
                                                 # multi-write() path to interleave/tear
    for i in (seq 1 50); crew status worker:$i working $big &; end; wait
    set -l physical (wc -l < $log)               # torn writes inflate physical line count
    set -l parseable (jq -c . $log 2>/dev/null | wc -l)  # torn lines fail to parse
    set -l uniq (jq -r .from $log 2>/dev/null | sort -u | wc -l)
    test $physical -eq 50 -a $parseable -eq 50 -a $uniq -eq 50; \
        and echo "ATOMIC-OK (50/50/50)"; \
        or echo "TORN: physical=$physical parseable=$parseable uniq=$uniq"
'
```

Expected: `ATOMIC-OK (50/50/50)`. This is now falsifiable: the 5 KB `detail` exceeds `PIPE_BUF`, so if the append weren't atomic a concurrent writer would split a line — inflating `physical` past 50 and/or dropping `parseable` below 50. If `TORN`, the atomic-append assumption is false — stop and report (forces a lock, or the gated SQLite upgrade).

## Task 3: read helpers — `roster`, `inbox`, `log`

**Files:**

- Modify (dev scratch): `/tmp/crew-dev/crew.fish`

- [ ] **Step 1: Add the three read cases** (before `case '*'`)

```fish
        case roster
            set -l crew (test -n "$argv[1]"; and echo $argv[1]; or echo $CREW_ID)
            test -f $log; or return 0
            jq -s --arg crew "$crew" '
                map(select(.crew_id==$crew and .kind=="status"))
                | group_by(.from) | map(max_by(.ts))
                | map({from, state:.body.state, pr_url:.body.pr_url,
                       age_s:((now - (.ts/1000))|floor)})' $log
        case inbox
            set -l crew (test -n "$argv[2]"; and echo $argv[2]; or echo $CREW_ID)
            test -f $log; or return 0
            jq -c --arg crew "$crew" --arg me "$argv[1]" \
                'select(.crew_id==$crew and (.to==$me or .to=="*"))' $log
        case log
            set -l crew (test -n "$argv[1]"; and echo $argv[1]; or echo $CREW_ID)
            test -f $log; or return 0
            jq -c --arg crew "$crew" 'select(.crew_id==$crew)' $log
```

Note: unlike `status`/`msg` (which hard-error on unset `CREW_ID`), the read helpers degrade to empty output when `CREW_ID` is unset and no crew arg is given (`--arg crew ""` matches nothing) — intentional, so a roster/log query never errors.
