## Step 1: `crew hold` in `adapters/core/crew.sh`

New subcommand, registered in the top-level `case "$sub"` beside `retro`, and added
to the usage string at `crew.sh:3115`. No test asserts that usage string, so it needs
no test update.

```
crew hold add --engine E --window W --resets-at EPOCH --agent A --ref R --branch B
              --tier T --model M --effort F [--plan P] [--mcp P] [--draft]
              [--shape S] [--spec FILE] [--crew ID] <title...>
crew hold list [--crew ID] [--json]
crew hold due  [--crew ID] [--json]
crew hold park <default> [--crew ID]
crew hold release <id> [--crew ID]
```

- [ ] **1a — flag-to-field map.** Every flag lands at exactly one JSON path. There is
      no inference and no defaulting between the two engine fields — `--engine` is
      the engine whose quota is being waited on, `--agent` the engine the task will be
      dispatched to, and SPEC §Q1 requires both populated.

      | flag | JSON path | required |
      | --- | --- | --- |
      | `--engine` | `wait.engine` | yes |
      | `--window` | `wait.window` | yes |
      | `--resets-at` | `wait.resets_at` (number) | yes |
      | `--agent` | `task.engine` | **yes** |
      | `--ref` | `task.ref` | yes |
      | | *bare digits on GitHub, so it compares directly against* | |
      | | *`claim-issue.issue`, which `dispatch.sh:158` writes with the* | |
      | | *`#` already stripped; the Linear id verbatim otherwise* | |
      | `--branch` | `task.branch` | yes |
      | `--tier` | `task.tier` | yes |
      | `--model` | `task.model` | yes |
      | `--effort` | `task.effort` | yes |
      | `--plan` | `task.plan` | no → null |
      | `--mcp` | `task.mcp` | no → null |
      | `--draft` | `task.draft` (bool, default `false`) | no |
      | `--shape` | `task.shape` | no → null |
      | `--spec FILE` | `task.spec` (a path, see 1c) | no → null |
      | `<title...>` | `task.title` | yes |

      Absent optionals emit real JSON `null`, never the string `"null"`.

      **Units, because two clocks meet here.** `wait.resets_at` is epoch **seconds**,
      matching `refresh-budget`'s own `resets_at`. `id` and the row's `ts` are
      **milliseconds**. So `due`'s `wait.resets_at <= now` and `park`'s
      `earliest - now` use jq's bare `now`, *never* the `now*1000|floor` idiom 1b
      mandates for `ts`/`id`. Mixing them is a factor-of-1000 error that 6a's
      boundary test would only catch after the fact.

- [ ] **1b — the write path.** Validate shape only, never the floor (SPEC §Q3):
      `--resets-at` must be all-digits **and strictly greater than `now`**; every
      `yes` row above must be present. Reject a missing one **by name**, the way
      `crew status` rejects an unknown state — fail loudly at the writer. - `mkdir -p "$dir"` before `_bus_append`, as `status|msg` does at
      `crew.sh:357`. `setup_repo` (`tests/helpers.bash:13-28`) creates a bare
      repo with no `.git/crew`, so the first `hold add` without `--spec` would
      otherwise fail its append — 1c's `mkdir -p` only runs on the spec path. - Take the millisecond clock from `jq -nc 'now*1000|floor'`, the idiom at
      `crew.sh:1102`, `:1217`, `:1245`. **Not** `date +%s%3N`, which is GNU-only;
      this file is deliberately macOS-portable (see the BSD-`dd` note at `:188`
      and "cksum is POSIX (portable to macOS)" at `:28`). - `id` is `<ms>-<pid>` — **milliseconds**, not `crew new`'s seconds
      (`crew.sh:311`); step 4c's duplicate guard compares it against the ms `ts` fields on
      `dispatch.sh:603` and `:1017`, and copying `crew new` would break that by a
      factor of 1000. - **Compute `ts` and `id` once, before the builder, and pass them in.**
      `_build_status` evaluates `now` _inside_ the builder (`crew.sh:386`), and
      `_fit_line` calls the builder repeatedly while shrinking — so an `id` minted
      inside would stop matching its own row's `ts` on any shrunk record. - **The builder closes over every fixed field and takes only the title.**
      `_fit_line` hands its argument to `_shrink`, which walks a JSON object and
      truncates _every_ string leaf (`crew.sh:202-210`) — passing the whole body
      would corrupt `id`, `task.branch` and `task.spec`. Mirror `_build_status`
      exactly: fixed fields via `--arg` from the enclosing scope, `$1` is the
      shrinkable title. - Set `crew_id` on the row, as `_build_status` and `_build_msg` do
      (`crew.sh:387`, `:408`) — step 1e's fold selects on it. - `to` is `hold:<crew>`, `from` is `dispatcher:<crew>`, `kind` is `msg`, and the
      body is the JSON **string** form the other synthetic sinks use. - **`add` prints the minted `id` on stdout** and nothing else, so the dispatcher
      can call `release <id>` and the tests can build assertions without going
      through `list --json`.

- [ ] **1c — the spec body.** `--spec FILE` copies the file to `<dir>/holds/<id>.md`
      (`mkdir -p` first) and records that path as `task.spec`. It is a file, not a
      field, because `DISPATCH_SPEC` is a caller-supplied temp path that will not
      survive a restart and a bus line must fit `_LINE_MAX` (4096, `crew.sh:180`).
      A `--spec` naming an unreadable file is an error, not a silent null.

- [ ] **1d — `--crew` and safety.** `hold` takes `--crew ID` exactly as `watch` and
      `stream` do, including the same character guard (`crew.sh:1059-1064`), falling
      back to `_crew_id` when omitted. The guard is for **consistency with the other
      two**, not containment — `<dir>/holds/<id>.md` embeds no crew id, so an
      unvalidated one could not escape the bus dir here anyway.

- [ ] **1e — the fold and the readers.** One shared jq fold: select
      `.crew_id==$crew and .kind=="msg" and .to==("hold:"+$crew)`, `fromjson` each
      body with `try … catch null` (the wart `crew retro` already handles), partition
      into adds (no `released`) and releases (`released == true`), and emit adds whose
      `id` is in no release. **Crew-scoped**, unlike `crew retro`, which deliberately
      has no crew filter (`crew.sh:2042`) — a hold belongs to one queue. - `list` → all outstanding. `due` → outstanding where `wait.resets_at <= now`
      (**matured is `<=`, not `<`**). - **Exit codes and empty output, stated because step 2 depends on them:** `due`
      exits **0 when any hold is matured, 1 when none** — including when `$log` does
      not exist. Do **not** copy `retro`'s `[ -f "$log" ] || exit 0` idiom
      (`crew.sh:2043`); it would report "matured" for an empty bus. With `--json`,
      `due` and `list` print `[]` on stdout when there is nothing, never empty
      output, so step 2c's array test is unambiguous. - `park <default>` → the branch default when nothing is outstanding or the
      earliest is already matured; otherwise `min(default, earliest - now)`.
      **Never print below 1**: `crew watch` rejects `--timeout 0`
      (`crew.sh:869-872`) and a 0 would fail the cursor re-arm. Validate
      `<default>` as a positive integer. - `release <id>` appends `{"id": "<id>", "released": true}` to the same sink.
      Releasing an unknown or already-released id is a **no-op that exits 0** —
      idempotent, because the release path can be retried after a crash. - Default (non-`--json`) output is a tab table with a header, matching
      `crew report` and `crew retro`.

**Verify:** `bash -n`, then `shellcheck adapters/core/crew.sh`.

## Step 2: `hold_due` in `crew stream` (implement: escalated)

`crew.sh`'s stream loop is the most delicate code in the file — a self-disarming
trap, a lock, a child process, and a `pending`/`$outf` drain whose ordering is
load-bearing. Change it narrowly and touch none of that.

- [ ] **2a — state.** Add `last_hold_key=""` and `last_hold_ts=0` beside the existing
      `last_err_key`/`last_err_ts` (`crew.sh:1170-1174`, under the comment at
      `:1168-1169`), initialized before `trap _stream_cleanup` is armed. Note for
      accuracy: `_stream_cleanup` does not reference either new variable, so the
      unbound-variable rationale in that comment does not itself apply to them —
      initialize there for symmetry with the pair they sit beside.
- [ ] **2b — the check.** At the **top of every loop iteration, immediately after the
      tick is written** and before the inner watch is spawned, so it fires on the
      batch path as well as the quiet path:
      `    matured=$(bash -euo pipefail "$0" hold due --crew "$crew" --json 2>/dev/null || true)`
      Shelling out to `$0` is the idiom the loop already uses for `watch`, and reuses
      step 1e's fold rather than duplicating it. The `|| true` is required: `due`
      exits 1 when nothing is matured, which under `set -e` would kill the stream.
- [ ] **2c — level-triggered emission.** `matured` is `[]` when nothing is matured
      (1e) — but it can also be the **empty string** when the shell-out itself fails
      and `|| true` swallows it, so guard for both:
      `case "$matured" in ''|'[]') … ;; *) … esac`. Do not reach for `jq length` on
      empty input under `set -e`. When non-empty, key on the sorted matured
      ids and emit only when the key changed or `--heartbeat` has passed since the
      last emission — the identical shape to the error path at `crew.sh:1256-1264`:
      `    {"stream":"hold_due","crew":"<id>","holds":[…],"ts":<ms>}`
      Reset `last_hold_key=""` when nothing is matured, so a hold released and later
      re-added announces again. Level, not edge: releasing one of three holds changes
      the key, so the remaining two announce on the very next iteration instead of
      waiting for a stream restart (SPEC §claude). Give `printf`/`jq` output
      `|| true`, like every other write in this loop — a reader that hung up must not
      abort it.
- [ ] **2d — placement, checked.** Between the tick write (`crew.sh:1219`) and the
      inner-watch spawn (`:1223`) is safe: `child` is empty there so
      `_stream_cleanup` has nothing to reap, the `|| true` covers `due`'s exit 1 under
      `set -e`, and `hold` acquires no lock (`_lock_acquire` callers: `crew.sh:904`,
      `:1126`, `:1158`, `:1806`, `:1963`, `:2850` — none of them `hold`), so it cannot
      race `watch.lock.d` or `stream.lock.d`.
- [ ] **2e — leave the rest alone.** No change to `quiet`, `pending`, `$outf`,
      `_stream_cleanup`, the lock, or `--status`. `hold_due` does **not** reset
      `quiet`: the heartbeat's backstop role is unaffected by a hold.

**Verify:** `bash -n`, `shellcheck`, then step 6b.

## Step 3: the floor verdict in `adapters/core/refresh-budget.sh`

This is the **only** place the last-15% test may appear. `crew.sh` gains no
threshold and no window-length table (SPEC §Q3).

- [ ] **3a — fold per engine, and touch only the ≥95% rows.** The advice renderer
      (`refresh-budget.sh:310-326`) iterates windows with no per-engine fold, so it
      cannot see a sibling window. Restructure it to, per engine: collect the ≥95%
      windows, decide **one** gating verdict, then emit rows.
      **Rows below 95% keep today's advice byte-for-byte** — they are not a hold
      decision. Only ≥95% rows gain a verdict. (This supersedes any reading of "one
      row per ≥85% window carrying the engine's verdict".)
- [ ] **3b — the gating window and the verdict, in precedence order.** Each rule picks
      **one** gating window; all other ≥95% rows on that engine defer to it. Where a
      rule could match several windows, take them in sorted key order so the choice is
      deterministic. **First:** any ≥95% window with `resets_at` null or `<= now` gates,
      verdict `not holdable: no reset time, hand the task back`, with no `binding window;`
      prefix — nothing could bind. **Then:** any ≥95% window whose `wsecs($k)` is null
      (`1d`/`unknown`/`other`) gates, verdict `not holdable: window has no nominal length,
hand the task back`, no prefix for the same reason. **Otherwise:** the gating window
      is the ≥95% window with the **greatest** `resets_at`, and the floor is
      `elapsed_pct($resets_at; $L) >= 85` on **that** window, reusing the existing local
      defs and adding no new number; its row is prefixed `binding window; ` and reads
      `holdable: inside the window's last 15%, wait past the reset` or
      `not holdable: <rem|reltime> is outside the window's last 15%, hand the task back`.
      Every ≥95% row that is **not** the gating window reads
      `not binding: <engine> is gated until <gating key> resets`.

- [ ] **3c — the five expected lines, verbatim**, so step 6c asserts on strings this
      plan fixed rather than ones the executor invented. The `(resets in …)`
      parenthetical and the `points ahead of pace` clause keep today's construction
      exactly; only the tail after the em dash changes.
      **Lines 2 and 3 cannot appear in one run** and belong to separate fixtures:
      an unsized `1d` at 99% fires rule 2 and gates the whole codex engine, so a
      sibling `5h` would read `not binding: codex is gated until 1d resets`, never
      `binding window; holdable`.
      `    budget lever: claude 7d at 97.0% — not holdable: no reset time, hand the task back
budget lever: codex 1d at 99% (resets in 6h 12m) — not holdable: window has no nominal length, hand the task back
budget lever: codex 5h at 99% (resets in 38m) — binding window; holdable: inside the window's last 15%, wait past the reset
budget lever: claude 7d at 97% (resets in 3d 22h, 53 points ahead of pace) — binding window; not holdable: 3d 22h is outside the window's last 15%, hand the task back
budget lever: claude 5h at 97% (resets in 38m) — not binding: claude is gated until 7d_opus resets`
- [ ] **3d — update the two assertions this breaks.** Both pinned rows are at 97%,
      i.e. ≥95%, so both change; step 7 demands a green suite. - `tests/refresh-budget.bats:115` — its fixture's `resets_at` is 2026-08-09,
      already past, so rule 1 fires. Replace with line 1 of 3c. - `tests/refresh-budget.bats:285` — elapsed is 44%, below 85, so rule 3 fires
      not-holdable. Replace with line 4 of 3c. - **Leave `:284` (claude 5h at 91%) and `:286` (codex 1d at 90%) untouched** —
      both are below 95%, and they are exactly the byte-identical-advice regression
      6c wants.
- [ ] **3e — a live inconsistency this fixes, at ≥95% only.** Today's `5h` advice
      (`refresh-budget.sh:321`) is unconditional on remaining time and contradicts the
      protocol's own "longer than that, shed as before". After 3b a `5h` window three
      hours out **and ≥95%** reads `not holdable`. An 85-95% `5h` row keeps the old
      text verbatim — `tests/refresh-budget.bats:284` pins exactly that, so do not
      reach below 95% to "finish" the fix.

## Step 6: tests

not in `tests/hold.bats`: 6b needs matured holds too, and a helper defined in the
former file is unreachable from the latter.
