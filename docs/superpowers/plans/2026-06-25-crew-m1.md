# crew M1 — harness integration (Implementation Plan)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Wire the M0 `crew` bus into the dispatcher harness so workers report lifecycle to the bus and the dispatcher watches `crew roster` instead of polling — plus slim worker startup. Issue #29, M1.

**Architecture:** `dispatch.fish` mints a per-session `crew_id`, stamps `crew_dir`/`crew_id` into `WORKER_TASK.md`, and launches workers with a minimal MCP profile. `WORKER_PROTOCOL.md` makes bus reporting mandatory (`joined→working→blocked/review→pr_open→done/failed`), runs `/deslop` before push, and `crew status blocked` + stops on an unresolvable permission escalation. `dispatch-notify.sh` (the `SessionEnd` backstop) appends an `exited` line for a worker that dies before a terminal status.

**Tech Stack:** fish, bash, `jq`, the M0 `crew` fish fn, Claude Code CLI (`--strict-mcp-config`/`--mcp-config`), Nix / Home Manager.

## Task 4: `dispatch-notify.sh` — append an `exited` bus line (guarded)

**Files:** Modify `home/ai/claude-code/dispatch-notify.sh`

The `SessionEnd` backstop must flag a worker that died mid-work — but must NOT override a clean `done`/`pr_open`/`failed`. So it reads the worker's last status and only appends `exited` if still in-flight.

- [ ] **Step 1a: Harden the existing `pane=` grep** (same `set -e`/pipefail latent bug plan-critic flagged — `grep -m1` exits 1 when the line is absent and aborts the script before its `[[ -n "$pane" ]]` guard). Add `|| true`:

```bash
pane="$(grep -m1 '^dispatcher_pane:' "$cwd/WORKER_TASK.md" | cut -d' ' -f2 || true)"
```

- [ ] **Step 1b: Append after the existing `tmux display-message` line** (keep that line). NOTE the `set -e`/pipefail-safe form — `|| true` on the grep, explicit `[[ -f "$log" ]]` guard before `jq` (a missing log is the _primary_ death case the backstop must survive), `|| true` on the read pipeline:

```bash
# crew backstop: if the worker died before a terminal status, record `exited`
# so the roster doesn't strand a `working` entry. Bash hook → inline append
# (can't call the fish `crew` fn); envelope matches crew.fish byte-for-byte.
crew_id="$(grep -m1 '^crew_id:' "$cwd/WORKER_TASK.md" | cut -d' ' -f2 || true)"
if [[ -n "$crew_id" ]]; then
  common="$(git -C "$cwd" rev-parse --path-format=absolute --git-common-dir 2>/dev/null || true)"
  if [[ -n "$common" ]]; then
    log="$common/crew/events.jsonl"
    me="worker:$branch"
    last=""
    if [[ -f "$log" ]]; then
      last="$(jq -r --arg c "$crew_id" --arg m "$me" \
        'select(.crew_id==$c and .kind=="status" and .from==$m) | .body.state' "$log" 2>/dev/null | tail -1 || true)"
    fi
    case "$last" in
      done|failed|pr_open) : ;;   # reached a meaningful end → don't override
      *)
        mkdir -p "$common/crew"
        line="$(jq -nc --arg c "$crew_id" --arg m "$me" \
          '{ts:(now*1000|floor), crew_id:$c, from:$m, to:("dispatcher:"+$c), kind:"status", body:{state:"exited"}}')"
        printf '%s\n' "$line" >> "$log"
        ;;
    esac
  fi
fi
```

- [ ] **Step 2: shellcheck** (required) — `shellcheck home/ai/claude-code/dispatch-notify.sh` → clean. Fix any finding.

- [ ] **Step 3: Local backstop harness** — run the hook against crafted temp repos; this is falsifiable and catches both `set -e`/pipefail bugs + the guard logic _without_ waiting for Task 6:

```bash
h=home/ai/claude-code/dispatch-notify.sh
run() {  # arg: last-status | "none" (no log) | "nocrewid" (task file lacks crew_id)
  t=$(mktemp -d); git -C "$t" init -q; git -C "$t" commit --allow-empty -qm i
  br=$(git -C "$t" rev-parse --abbrev-ref HEAD); log="$t/.git/crew/events.jsonl"
  if [ "$1" = nocrewid ]; then printf 'tier: trivial\n' > "$t/WORKER_TASK.md"
  else printf 'crew_id: t1\n' > "$t/WORKER_TASK.md"; fi
  if [ "$1" != none ] && [ "$1" != nocrewid ]; then
    mkdir -p "$t/.git/crew"
    jq -nc --arg b "worker:$br" --arg s "$1" \
      '{ts:1,crew_id:"t1",from:$b,to:"dispatcher:t1",kind:"status",body:{state:$s}}' > "$log"
  fi
  printf '{"cwd":"%s"}' "$t" | bash "$h"; ec=$?
  ex=no; [ -f "$log" ] && jq -e 'select(.body.state=="exited")' "$log" >/dev/null 2>&1 && ex=yes
  echo "$1 -> exited=$ex exit=$ec"
}
run none; run working; run done; run pr_open; run nocrewid
```

Expected:

```
none -> exited=yes exit=0       # died before any status → backstop fires (catches the missing-log set -e bug)
working -> exited=yes exit=0    # in-flight → fires
done -> exited=no exit=0        # terminal → skipped (no override)
pr_open -> exited=no exit=0     # meaningful end → skipped
nocrewid -> exited=no exit=0    # no crew_id → clean exit, no error (catches the grep set -e bug)
```

Any `exit!=0`, or `none`/`working` showing `exited=no`, means a guard/`set -e` bug — stop and fix.
