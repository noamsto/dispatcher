# dispatch.sh restructuring design

**Purpose.** Decide how to restructure `adapters/core/dispatch.sh`: the module boundaries, the language of each part, and the order to move it in. Issue: #1428.

**Status.** Proposal, not implemented. This document changes nothing in `adapters/core/`, `crew/`, the tests or `flake.nix`.

**Pinned revision.** `e9da5bef`. Every `path:line` citation and every size is at this commit. Check a citation with `git show e9da5bef:<path>`. Line numbers stay valid at the pin after `main` moves; they do not track `main`.

**Conventions.** "Measured" means counted at the pin with the stated definition. "Estimated" means projected from a measured base with the stated method. New files named in sections 3 and 4 (for example `adapters/core/launcher-common.sh`, `tests/trust-pins.tsv`) do not exist yet.

**Taxonomy.** One set of classes, used for every commit and follow-up in this section.

| Class                         | Meaning                                                                                                                                                                                                                                                      |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Duplicated helpers (DUP)      | The defect or the fix cost depends on one rule existing in more than one launcher.                                                                                                                                                                           |
| Gate ordering (ORD)           | Two checks or a check and a side effect ran in the wrong order, or shared one failure path.                                                                                                                                                                  |
| Implicit boundary state (IMP) | Behaviour depends on which process, side of the wire or context the code runs in, and the script infers that from an env var or tmux state instead of receiving it. This class is wider than state across subshells, and no item is across subshells proper. |
| Reader spread (RDR)           | The fix had to change more than one reader of the same state.                                                                                                                                                                                                |
| Convention gap (CONV)         | No shared convention or contract exists, so each site hand-rolls one.                                                                                                                                                                                        |
| Shared mutable globals (SMG)  | The defect came from one piece of code mutating a global another relied on. Count: 0.                                                                                                                                                                        |
| Untestable paths (UNT)        | The defect escaped because the path could not be tested. Count: 0.                                                                                                                                                                                           |
| Ordinary bug churn (OBC)      | A missing case, policy correction or wrong assumption about an external tool, fixed locally. No restructuring would have prevented it.                                                                                                                       |

**Rule used to decide.** Classify by what had to differ for the defect not to exist, not by the shape of the fix. ## 3. Designs

Four designs. D is a sequence of narrowed versions of B and C.

- **A. Go `crew dispatch` replacing the script.** The whole flow moves to Go. `adapters/core/dispatch-resume.sh` has to move with it, because it shares 40-plus helpers and would otherwise be left with copies of a deleted original.
- **B. Bash libraries split with `source`.** The file is cut into libraries by responsibility, baked with `sub`, with a thin entry script.
- **C. Hybrid: thin bash launcher over Go decisions.** Go makes the decisions (parse, tier and model, gates, claim evidence) and returns a plan. Bash performs the side effects (tmux, `wt`, launch).
- **D. Sequence (recommended).** First a single shared bash library for the launcher copies. Then the side of the wire becomes explicit. Then `--role-watch`, the one region with a clean process boundary, moves to a `crew` subcommand. The main flow stays bash. Named bash phases, and C-style Go decisions for claim evidence and the tier gate, are later and optional.

### Design A: Go `crew dispatch`

**Migration risk: high.** The earlier port moved independent subcommands (`docs/crew-go-port.md:1-17`). `adapters/core/dispatch.sh:5080-7353` is one sequence with interleaved gates and side effects, for example `mkdir` at `adapters/core/dispatch.sh:5920`, `gh issue create` at `adapters/core/dispatch.sh:6177`, the switch cases from `adapters/core/dispatch.sh:6357`. No equally independent seams are visible in it. A mixed period needs an older peer's `dispatch` to keep working through `crew remote-run` (`adapters/core/dispatch.sh:4321-4323`).

**Tests.** `tests/dispatch.bats` has 1,141 cases; 1,074 (94.1%, measured) are black-box against the script and would survive a language change in principle. They invoke it as `bash -euo pipefail "$DISPATCH"` (`tests/dispatch.bats:5-8`), so the harness entry has to change. 19 text-coupled cases are rewritten. Substitution-coupled means the case runs a `sed`-substituted copy of the script: 3 cases do that inline (`tests/dispatch.bats:2088`, `tests/dispatch.bats:4552`, `tests/dispatch.bats:4568`) and 5 more through `_substituted_dispatch` (`tests/dispatch.bats:152`). Those 5 are inside the 1,074 black-box count, and all 8 change with the baking mechanism. 45 cases source a lib directly (43 `adapters/core/grant-check.sh`, 2 `adapters/core/claude-worker-settings.sh`) and keep working if those libs stay. The 11 parity guards go, and the sibling launchers lose the file those guards compare against. `TestDriftAgainstBash` and `TestRowsMatchBash` lose the file they extract from (`crew/internal/frame/frame_test.go:231`, `crew/internal/frame/frame_test.go:336`, `crew/internal/frame/frame_test.go:564`). Timing evidence favours Go for this kind of table-driven work (`docs/test-harness-decision.md:89-95`), but a comparison over the whole of `tests/dispatch.bats` has not been measured. Other files pin the script path and would change too: `tests/live/dispatch-window.sh:133`, `tests/harness/go/role_watch_test.go:333`, `tests/harness/pytest/test_manifest.py:636`, `tests/harness/shellspec/case-runner.sh:9`, `scripts/bats-affected.sh:80`, `scripts/bats-coverage.sh:252`.

**Nix.** `crewGo` has `src = ./crew` (`flake.nix:112`) and cannot read `adapters/core/` at build time. Of dispatch's 18 baked values, 14 are not in crew-go today (the four that are: `flake.nix:117`). Baking `@protocolDir@` through `-X` would rebuild crew-go and re-run its tests for every protocol edit: 76 commits in the `--since=2026-10-09` window (measured). `@skillsDir@` varies per configuration (`flake.nix:63-68`), and baking it would vary crew-go too. `@worktreeGitLib@` bakes `crew-go` (`flake.nix:124-127`) and `@launcherRuntimePath@` covers `crew` (`flake.nix:145-152`, `flake.nix:236`), so neither can be baked into crew-go without a cycle. The way out is to pass values at run time from a thin wrapper, as `dispatch-config` (`flake.nix:144`) and `CREW_GO_BIN` (`adapters/core/worktree-git.sh:23-25`) already do. So a `dispatch` wrapper stays either way, and it stays launchable with no eval cycle: the wrapper would depend on `crewGo`, which references nothing else in the flake (`flake.nix:98-104`). `crew`'s PATH (`flake.nix:194`) also lacks `direnv`, `diffutils` and `lead-launcher`, which dispatch carries (`flake.nix:236`).

**Sizes.** See Sizing.

### Design B: bash libraries split with `source`

**Migration risk: low to moderate.** Mechanical moves. New hazards: `source` order becomes a hidden dependency. A sourced file escapes the `writeShellApplication` shellcheck, though CI lints `adapters/core/*.sh` directly (`flake.nix:374-380`).

**Tests.** Functions leaving the file break the column-0 anchors in `tests/adapters.bats:62-126`, `tests/model-map.bats:136-155`, `tests/dispatch-resume.bats:863-923`, `tests/refresh-budget.bats:2308` and `tests/adapters.bats:2918`. Copies retired by the split are replaced by a single-definition guard, as `tests/dispatch-resume.bats:876-910` already does for the grant-check functions. If the frame block leaves `adapters/core/dispatch.sh`, `crew/internal/frame/frame_test.go:205-210` becomes fatal under `CREW_DRIFT_REQUIRED=1`. No speed gain.

**Nix.** Cheap. `${./adapters/core/launcher-common.sh}` added to `sub` touches only the shell wrappers (`flake.nix:128-131`), not `crewGo`. No new cycle. The placeholder constraint described under Design D applies to every split library.

**Effect on the evidence.** Answers DUP only. Moves the main flow's globals to more files without reducing them. A full split gives navigation and little else that the evidence asks for.

### Design C: thin bash launcher over Go decisions

**Migration risk: moderate to high.** A new boundary is the product of this design: a typed plan handed from Go to bash, whose schema is new and must stay compatible across `--host` peers. Decisions are interleaved with side effects (the claim gate at `adapters/core/dispatch.sh:6008-6099` runs after the crew dir is created at `adapters/core/dispatch.sh:5920`), so a single up-front "decide" call changes the order unless decisions run in several rounds.

**Tests.** Black-box bats stays unchanged if the entry stays. New Go unit tests would cover the decisions.

**Nix.** Decisions need settings (`dispatch-config`, already passed at run time) and little else. `@modelResolve@`, `@budgetGateLib@`, `@localModelsLib@` are already crew-go ldflags (`flake.nix:117`).

### Design D: sequence (recommended)

**Migration risk: low through S5, moderate for S6 to S8.** Each slice is one PR, and the production-code slices (S3 onward) are preceded by pins from S1 and S2.

**Tests.** S3 and S4 replace the parity guards with single-definition guards. The black-box suite and `run_dispatch` stay. S6 to S8 port the role-watch family to Go tests. The `--role-watch` entry stays as an exec shim until in-flight workers have drained, which also keeps the harness entries that run the script directly working (`tests/harness/go/role_watch_test.go:333`, `tests/harness/pytest/test_manifest.py:636`, `tests/harness/shellspec/case-runner.sh:9`). S8 retires `TestDriftAgainstBash` and `TestRowsMatchBash` (`crew/internal/frame/frame_test.go:336`, `crew/internal/frame/frame_test.go:564`).

**Nix.** S3 adds one `sub` token (`flake.nix:128-131`); `lead-launcher` gains `sub`, which its build does not use today (`flake.nix:275`). The library stays placeholder-free. A file baked by `${./...}` keeps its text raw, and S4 moves helpers that carry placeholders: `_check_protocol_rev` (`adapters/core/dispatch.sh:2114`, `adapters/core/dispatch-resume.sh:477`), `_settings_load` (`adapters/core/dispatch.sh:1688`, `adapters/core/dispatch-resume.sh:1031`), `_model_class` and `_class_sigil` (`adapters/core/dispatch.sh:1861`, `adapters/core/dispatch.sh:1980`, `adapters/core/dispatch-resume.sh:1058`, `adapters/core/dispatch-resume.sh:1099`). A raw `@protocolRev@` starts with `@`, hits the sentinel at `adapters/core/dispatch.sh:2120` and silently turns the staleness check into a warning (F13 to F15). So each launcher keeps its baked values in its own `sub`-rewritten text and passes them to the library as variables or parameters, keeping the literal `stamped_rev="@protocolRev@"` line in the launcher. That leaves `tests/module.bats:797-832`, which greps `stamped_rev="<hex>"` in the built launchers, and the five `_substituted_dispatch` cases (`tests/dispatch.bats:152`, `sed` on `$DISPATCH` only) true without change. The rejected alternative is a `replaceStrings` bake of the library, like `worktreeGitLib`'s (`flake.nix:124-127`): the library would need its own bake step, and those two tests would have to change. `adapters/core/dispatch-notify.sh` keeps its `_bus_append` copy because it ships as raw plugin text (`scripts/gen-adapters.sh:147`, `scripts/gen-adapters.sh:188`). Its guard must compare the whole function, not the signature line. `crew role-watch` needs no baked value: the arm uses no `@placeholder@` (measured over `adapters/core/dispatch.sh:2886-3862`). So crew-go's inputs do not change. Role-watch edits then rebuild and re-test crew-go, as any other file under `crew/` does (`flake.nix:112`).

### Trust boundary

**What can go wrong.** A refactor drops or reorders an _invocation_, not a check body. The bodies mostly live in `adapters/core/worktree-git.sh:41-47` and `adapters/core/worktree-git.sh:117-159`, over `crew-go git-guard` (`crew/main.go:250`, `crew/internal/gitguard/guard.go`). The invocations sit in `adapters/core/dispatch.sh` and `adapters/core/dispatch-resume.sh`.

**How a refactor is prevented from dropping one.** Slice S1 adds `tests/trust-pins.tsv` and `scripts/trust-mutate.sh`. The manifest has one row per ID below: file, invocation pattern for one or more sites, replacement, test filter, expected refusal. S1 adds and verifies the 50 rows whose invocation is in `adapters/core/dispatch.sh` (M1 to M15, H1, H2, R1, R2, W1, F1 to F3, F6, F7, F9 to F11, F13, F14, F16, F17, F19 to F27, F30 to F36). S2 adds and verifies the other 24 (D1 to D10, P1, P2, LL1, CR1, CR2, F4, F5, F8, F12, F15, F18, F28, F29) and extends the tool to Go rows for CR1 and CR2. The tool rewrites each site with the row's replacement, keeping the surrounding syntax, rather than deleting the line, because a deletion can break the syntax or the compile and go red for the wrong reason (M1 and M2 share one `if` at `adapters/core/dispatch.sh:5924`). One no-op cannot serve every row: `_artifacts_dir_bad` and `_protocol_dirs_record_bad` succeed when they find an offender (`adapters/core/dispatch.sh:2729`, `adapters/core/dispatch.sh:6959`), so a `true` would force the refusal on and report a false pin, and inline checks (F22 at `adapters/core/dispatch.sh:2936`, F32 at `adapters/core/dispatch.sh:6373`, F33 at `adapters/core/dispatch.sh:6284`, D5a, D5b) have no invocation to swap. So the replacement is set per row (`true`, `false` or a condition rewrite), and it must make the guard pass, so the row proves the guard was dropped rather than forced on. It requires `bash -n` or a clean compile first, runs the row's filter, requires a red result and restores the line. A red result counts only if the failing assertion is the row's expected refusal or side-effect assertion. Rows covering several sites (M8b, M10b, D5a, D5b, F22, F34) get one mutation per site. M13, H2, R2, P2 and CR2 reuse a sibling row's invocation, so they add a test filter, not a mutation. Grouped rows neutralise all their named sites together and require red, because a second site refuses identically and a single deletion cannot go red: D1 and D8 on `adapters/core/dispatch-resume.sh:898` and `adapters/core/dispatch-resume.sh:899` (`Check` runs `Pin` first, `crew/internal/gitguard/guard.go:12-18`), and D7 on `adapters/core/dispatch-resume.sh:792` and `adapters/core/dispatch-resume.sh:617` (`target` only comes from a positional, so `adapters/core/dispatch-resume.sh:792` always precedes `adapters/core/dispatch-resume.sh:617`). Dropping one site of such a pair is deliberately invisible, because the pair is defence in depth. That is about 76 mutations, two of them grouped, and about 82 filter runs, with D8 adding a filter to D1's group (estimated by counting sites in the tables). CI runs the tool on PRs touching any path in the manifest's file column, so a moved invocation moves the trigger: that takes in `adapters/core/permission-check.sh`, `adapters/core/lead-launcher.sh`, `crew/internal/reap/reap.go`, after S3 and S4 `adapters/core/launcher-common.sh`, and after S6 the `crew/` paths for W1 and F22 to F24. At 3 to 5 s per run that is 4 to 7 minutes, but the per-run figure comes only from the role-watch family (`docs/test-harness-decision.md:49-56`), so the CI cost is an unmeasured assumption. A move changes the row in the same PR, so it is visible in review. A move past what the check protects is caught by the row's test, which asserts the later side effect did not happen. A pin that cannot be made red is a finding, not a pass. An engine's auto-mode classifier may refuse a worker that disables guards, even in a scratch copy, so S1 and S2 should go to a worker able to run the mutation tool, or the tool should run only in CI with the worker authoring the manifest and the tests.

### Recommendation

**Adopt D.** Reasons, in order of weight:

1. **It answers the strongest evidence for the least cost.** One shared bash library answers two of the three DUP items and reduces 10 of the 11 parity guards. It costs a precedent the repo already uses (`flake.nix:124-131`), it does not touch crew-go, and it removes up to 870 duplicated lines (measured count; the removal is estimated), for a net -850 to -810 production lines through S4 (estimated). The exact figure will differ, because S4 reconciles 8 helpers that are not all checked copies and `adapters/core/dispatch-notify.sh` keeps its `_bus_append` copy.
2. **It respects what the evidence says about the main flow.** Zero defects are attributed to shared globals or untestable paths, and 33 of 46 commits are features. A 2.2 to 3.0 times port of 7,353 lines (estimated 16,000 to 22,000 Go production lines) is out of proportion to that evidence. The Nix cost is real too: baked values would rebuild crew-go on protocol edits, or need a wrapper regardless.
3. **Role-watch is the one region where Go clearly pays.** It is a separate long-running process. Most of its frame predicates (211 lines, measured, `adapters/core/dispatch.sh:3000-3210`) already exist in Go. Keeping it in bash is what forces the indent-anchored frame extraction, and one of the two stated reasons for the shfmt exclusion. Its wait-heavy tests are the largest measured lever on suite time (`docs/test-harness-decision.md:196-206`). `crew stall-watch` is a close precedent at a measured 2.19 ratio.
4. **It is safe to stop early.** Pins and the shared library are worth having on their own. Precedents for small moves into `crew` exist (`cdcfc113` moved fleet leads, net -80 lines in the file; `crew remote-run` at `crew/main.go:238`; `git-guard` called from the shared lib at `adapters/core/worktree-git.sh:41-47`), so later moves stay open without committing to them now.

**What would change this recommendation.**

- A measured feature-cost signal: if, after S9, new features still routinely need the same edits in several parts of the main flow, S10 is worth doing and a larger move deserves another look.
- A language-level requirement: hosts where `bash` 5 semantics or the bash runtime cannot be assumed, which would make A's cost necessary.
- Test speed as the owner's top priority: the `tests/dispatch.bats` table-driven sweeps are fork-bound and bash-bound (`docs/test-harness-decision.md:202-206`).
- If S6 costs more than 3.0 times the 766 lines outside the extracted block, or if behaviour cannot be kept across the cut-over in S7, stop and keep role-watch in bash, with the classifiers moved out only if that alone is worth it.
