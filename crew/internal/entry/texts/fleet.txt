usage: crew fleet [--all] [--crew ID] [--json]

One row per live branch across every crew bus on the machine, from any
directory (no git repo needed). Buses come from the repo registry plus a walk of
$CREW_SWEEP_ROOTS (colon-separated; default $HOME). Rows are the roster's, with
a repo column; by default only working, blocked and pr_open branches show. A
crew whose newest remote dispatch (`dispatch --host`) is under 24 hours old and
whose branch is not reaped is listed even when none of its workers has a local
status row.

  --all       Every branch, whatever its state
  --crew ID   Only this crew id
  --json      A JSON array of roster rows plus repo and crew_id

Peer hosts' rows come tagged `peer: true` and `host`; one naming a local crew id
or worker branch is dropped (counted on stderr), as in `crew roster --peers`.

Repos that are unreadable or gone are noted on stderr and skipped.

  crew fleet --json | jq -r '.[] | [.repo, .branch, .state] | @tsv'

usage: crew fleet stream --crew ID [--rediscover S] [--states a,b,c] [--park S]
                         [--heartbeat S] [--coalesce S] [--retry S]
                         [--interval S] [--force]
       crew fleet stream --status --crew ID

One long-running lane that delivers a crew's bus events from every repo on the
machine, so a dispatcher whose workers land in other repos needs one Monitor
instead of one `crew stream` per repo. Lines are `crew stream`'s, and each batch
carries a top-level `repo` (the label `crew fleet` shows); error lines name the
repo they concern, and the lane's own heartbeat has none.

  --crew ID       The crew to follow (required; no ambient CREW_ID)
  --rediscover S  Look for newly joined buses every S seconds (default 300)
  --status        Report the lane (alive, stale or dead; exit 0, 1 or 2)
  --force         Replace a live lane, as `crew stream --force`
  the rest        As `crew stream`; --reap-every is refused

A bus joins once it holds a row for the crew, so no cursor is ever seeded in an
unrelated repo. It uses the same per-crew cursor `crew watch` keeps there; a
repo joined with no cursor file replays its backlog of qualifying events on its
first park, as a bare `crew watch` does.

hold_due and reap stay per repo: the fleet lane does not run reaps and does not
evaluate holds. The per-repo `crew stream` or `dispatch` does. A bus whose
per-repo stream is alive is left to it (noted once on stderr), so one event is
never delivered twice. A per-repo stream started while the fleet lane is
mid-park shows `another watch is already running` error lines until that park
ends (at most --park seconds).

Like `crew stream`, the lane holds the watch for each repo it has joined, so a
bare `crew watch` for that crew in that repo is refused ("another watch is
already running") while the lane runs.

The lane lock lives under
${XDG_STATE_HOME:-~/.local/state}/crew/fleet-stream/<crew>, outside every repo.
Gone repos and repos without a bus are noted once on stderr and skipped.

  crew fleet stream --crew <crew-id>

usage: crew fleet load [--json] [--budget N] [--add WEIGHT] [--own BRANCH]...

How loaded the machine is, from any directory (no git repo needed): the live
lead weight against fleetBudget, and the 1-minute load average against the core
count. This is the check every `dispatch` runs. A live lead is a pane stamped
with a branch, and no role or role `lead`, running an engine in a worktree that
still exists, whose branch has not posted done, failed, exited or reaped. It
weighs its WORKER_TASK.md tier: trivial 1, standard 2, deep 3 (an unreadable
header counts as standard). Role panes add nothing.

  --json         The document: {budget, weight, pending, free, leads[{repo,
                 branch, name, tier, weight}], load1, cores, load_over,
                 engines{<e>: {in_budget, hot_windows, limit_reached}},
                 budget_age_s}. free is null when fleetBudget is 0, which
                 turns both checks off; load1 and cores are null when the host
                 does not say; an engine reads in budget when the quota cache
                 cannot tell (missing, over 2 h old)
  --budget N     Use this fleetBudget instead of asking `dispatch-config`
  --add WEIGHT   Judge a dispatch of this weight: exit 0 fits, 3 refuses and
                 prints why (to stderr with --json), 1 is an error
  --own BRANCH   That dispatch's own branch; one that already has a lead pane
                 (engine alive or not) is no new lead and always fits

Load comes from $DISPATCH_LOADAVG_FILE, else /proc/loadavg, else `sysctl -n
vm.loadavg`; cores from `nproc` on PATH, else `sysctl -n hw.ncpu`. An unreadable
one skips the load check.

  crew fleet load --json | jq '.free'

usage: crew fleet status [--json] [--gh]

The cold-start view of the whole fleet, rebuilt from durable state on disk from
any directory (no git repo needed, no memory of earlier runs): which
dispatchers are alive, which workers are blocked and for how long, which PRs
await merge, which holds wait, and how loaded the machine is. Buses are found
as `crew fleet` finds them.

  --json   One document: {ts, host, machine, queue, repos[{repo, common,
           misrouted, crews[{crew_id, dispatcher{state, pid, pane, lane,
           last_event_s}, attention, workers[], holds[], overseer_inbox[]}]}],
           skipped[{path, status}]}. state is live, dead or closed (no pid
           file); lane is the stream tick's alive, stale or dead, null when no
           tick was written; attention is attended while the dispatcher is
           live, else unattended or idle by whether the crew has live work or a
           hold. A worker
           is its roster row plus blocked {since, cycle, budget_left_s, source,
           answered} (the first row of its current run of blocked rows),
           finished_window, remote_unprobed and pr_candidate. machine is
           `crew fleet load`'s document, null when fleetBudget cannot be read
           (the reason goes to stderr); queue is the fleet hold queue's {head,
           demoted[], parked[]}, as `crew fleet queue` lists it. overseer_inbox lists a crew's dispatcher msgs to
           overseer:<host> after the overseer's cursor, else from the last 24 h;
           msgs from any other sender only count in misrouted
  --gh     Ask GitHub about each PR candidate (a pr_open or done row with a
           pr_url that is not reaped), four at a time, 20 s each; only a PR of the
           repo whose bus the row is on is asked for, any other pr_url is a
           pr_error. Adds pr
           {state, merge_state, review, checks: pass|fail|pending} or, when the
           lookup fails, pr_error. Never fails the command

Without --json, one line per crew: REPO CREW DISPATCHER LANE LIVE
BLOCKED(oldest) PR_OPEN HOLDS. With CREW_OVERSEER set no remote host is asked:
a remote worker is its dispatch row with remote_unprobed true. Gone repos and
repos without a bus land in skipped; the exit status is 0 with a document.

  crew fleet status --json --gh | jq '.repos[].crews[] | select(.attention == "unattended")'

usage: crew fleet queue [--json] [--admit WEIGHT [--hold ID] [--own BRANCH]...] [--crew ID]

The machine-wide queue of fleet holds (`crew hold add --fleet`), from any
directory (no git repo needed), across every repo in the registry. Holds are in
queue order: repo priority (`crew fleet prio`), then hold prio, then the repo
whose newest fleet release is oldest, then the hold's age. STATE is due (the one
hold the gate admits now), waiting, demoted (it was due and its dispatch did not
start within fleetHeadTimeout, so it queues behind the rest) or parked, with the
reason: oversize (heavier than fleetBudget), demoted (demoted a second time) or
ineligible (its crew has no live dispatcher, or its lane is dead or stale).
Read-only: it never writes fleet-due.json or the bus.

  --json         The document: {ts, budget, free, load_over, due, head,
                 holds[{repo, common, crew_id, id, branch, prio, repo_prio,
                 weight, ts, waited_s, state, reason, first_due, demoted_at}]}.
                 due and head are null when there is none
  --crew ID      List only this crew's holds
  --admit WEIGHT Judge a new lead of this weight against the queue: exit 0
                 admits it, 3 refuses and names the first hold in order on
                 stdout, 1 is an error. It is refused while a hold that can
                 bind waits, unless it re-dispatches a branch that already has
                 a lead pane (--own) or is the release of the due hold (--hold)
  --hold ID      The fleet hold this dispatch releases
  --own BRANCH   That dispatch's own branch; repeatable

  crew fleet queue --json | jq '.head'

usage: crew fleet prio <repo> <n>

Set a registered repo's priority in the fleet queue, on the human's word. 0 is
the default and resets it; higher goes first, and n may be negative (`crew
fleet prio <repo> -3`). <repo> is the repo's git common dir, a checkout of it,
or its name as `crew fleet` shows it; it must be in the registry. n is a whole
number within one million either way.

Refused in a worker or role session and in a crew-stamped pane, so a worker
cannot rank its own repo ahead of the rest. The priority is written to
${XDG_DATA_HOME:-~/.local/share}/crew/fleet-priority.json and every change
appends one line (time, repo, old, new, caller) to fleet-priority.log beside it.

  crew fleet prio acme/api 5
