usage: crew crews [--mine | --home | --legacy]

List every crew of this repo: its own store under the state root, or a crew dir
or an id on this repo's bus. Each row has id, last and first event, worker
count, dispatcher pid and whether that pid is alive. Both repo-bus sources count
— a crew dir alone (watch creates one) and an id seen only in the log. Run
outside a repo, it lists the layout-2 crews with no home repo.

  --mine    Print only the crews this caller owns — one id per line, no header —
            meaning the crews whose recorded dispatcher pid is a live ancestor of
            this process: the one it registered plus any 'crew adopt' re-attached
            to it. A dispatcher that adopted a restarted crew's workers uses this
            to watch every crew at once.

  --home    List only the crews homed in this repo, not ones that merely dispatched
            workers into it from another repo. Exclusive with --mine. A crew is home
            by its homes/<id> record (written by register and adopt); a crew with
            no record, or one naming another repo, counts when its pidfile.log has
            a register or adopt ok/forced line, or its live dispatcher pid runs in
            this repo.

  --legacy  Print the live layout-1 crews of this repo — one id per line, no
            header — the phase 6 deletion gate, which deletes the layout-1 code
            only once this prints nothing on every host. Layout 1 means "resolves
            to layout 1 here": a repo dir beside a meta.json is layout 2 and is
            not reported. Live means the recorded dispatcher pid is alive and not
            a recycled pid, the same rule the alive column and --mine use; the
            listing deletes nothing, so a dir left by a killed dispatcher stays
            put until phase 6. Exclusive with --mine and --home.

  crew crews
  crew crews --mine
  crew crews --home
  crew crews --legacy
