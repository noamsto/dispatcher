usage: crew where <target> [--crew ID] | crew where --log|--dir [--crew ID] | crew where --json [--crew ID]

A human-usable address for a worker's pane: codename, session:window.pane, window
name, role and the jump command.

  <target>  Codename (lime), branch, or a tmux pane id such as %N
  --crew    Crew id; defaults to this repo's crew
  --log     Print the crew's bus log path instead (no target, no tmux)
  --dir     Print the crew's own directory instead (no target, no tmux)
  --json    Print one JSON object instead (no target, no tmux; excludes --log, --dir)

--json prints, in this key order:
  {"crew_id","layout","dir","log","repo_dir","meta"}
layout is 1 or 2; dir and log are the paths --dir and --log print; repo_dir is
the repo's crew dir, or null for a layout-2 crew resolved outside a repo; meta
is null for layout 1 and for layout 2 the crew's meta.json:
  {"layout","id","created","home_host","home_repo","home_slug","visiting",
   "created_by","dispatcher_session"}
home_repo may be null; home_slug and dispatcher_session are omitted when empty.
A refusal prints nothing on stdout.

--log, --dir and --json resolve the crew from --crew, the task doc, then $CREW_ID.
A layout-2 crew answers outside a repo too; a layout-1 crew needs its repo. An
archived or index-only crew is refused with exit 3, any other failure exits 1.

A worker dispatched to a remote host answers with its line and ` [host H]` after
it: the local mirror window's when there is one, else the host's own. A target
that names a local and a remote worker is refused; a `%id` is never routed.

A <target> is resolved from dispatcher-anchored state only — never git discovery
in a worktree or the caller's env (only --log and --dir read those). Non-zero
with a readable message when the pane is gone.

  crew where lime
  crew where --log --crew c-1a2b
